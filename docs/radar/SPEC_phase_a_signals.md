**덮어쓰지 않는다.** 주마다 행이 쌓이고, 이것이 뉴스 축의 baseline 재료이자 나중에 "테마 라이프사이클" 분석의 원본이 된다.

## 2. A-3: 뉴스 축

### 2.1 수집

- `themes.yaml`의 `keywords_ko` / `keywords_en`을 OR로 묶어 검색
- 미국 = `keywords_en`, 한국 = `keywords_ko` (Phase A는 영어만)
- 주 단위는 **월요일 00:00 ~ 일요일 23:59 (현지 기준 아닌 UTC 고정)**

### 2.2 중복 제거 — 이게 가장 중요하다

**같은 기사가 여러 매체에 재배포되는 것을 걸러내지 않으면 건수가 무의미해진다.** 통신사 기사 하나가 20개 매체에 실리면 건수가 20으로 잡힌다.

```
1. URL 정규화 후 해시 (쿼리스트링·트래킹 파라미터 제거)
2. 제목 정규화 후 비교 — 공백·특수문자 제거, 소문자화
3. 정규화 제목이 동일하면 1건으로 취급
4. 제목 유사도 90% 이상도 1건으로 취급 (선택. 구현 부담되면 3까지만)
```

**중복 제거 전후 건수를 둘 다 로그에 남긴다.** 제거율이 주마다 크게 흔들리면 수집 소스에 문제가 있다는 신호다.

### 2.3 판정

```
baseline = 직전 4주 news_count 평균 (이번 주 제외)
ratio    = news_count / baseline

news_count < min_articles  → 'na' (판정 보류)
baseline 데이터 4주 미만    → 'na'
ratio >= 2.0               → 'up2'  (↑↑)
ratio >= 1.3               → 'up1'  (↑)
ratio <= 0.7               → 'down' (↓)
그 외                       → 'flat' (→)
```

`min_articles`는 `themes.yaml`의 테마별 값, 없으면 `config.default_min_articles`(10).

### 2.4 콜드 스타트 — 반드시 처리할 것

**baseline이 없으면 뉴스 축이 4주간 전부 `na`다.** 즉 툴을 켜고 한 달간 화면이 거의 비어 있다.

**해결: 초기 백필.** 뉴스 API가 날짜 범위 검색을 지원하므로, 셋업 시 **직전 8주치를 소급 수집**한다.

```
backfill-news.yml (workflow_dispatch)
  입력: weeks (기본 8), theme_id (선택)
  동작: 주 단위로 나눠 과거 기사 수집 → theme_news, theme_signals 채움
```

8주를 넣으면 첫 실행부터 baseline 4주가 확보되고 4주치 추이도 볼 수 있다.

**주의**: 과거 기사 검색은 API에 따라 결과가 현재 검색과 다를 수 있다(색인 변경, 기사 삭제). 백필로 만든 baseline은 실시간 수집보다 낮게 나오는 경향이 있어 초기 몇 주는 ratio가 과대평가될 수 있다. `backfilled = true` 플래그를 남기고, 첫 4주 판정은 참고용으로만 본다.

### 2.5 미국 뉴스 축 — 소속 기업 뉴스 건수 (2026-10-04 변경)

구글 뉴스 RSS가 2026-09-28부터 GitHub Actions IP를 막았고, 대체로 시험한 GDELT DOC API는 공유 IP 요율
제한(10회 중 6회 실패)과 수집 공백(2026-09-14 주 전 테마 5% 수준) 때문에 쓸 수 없었다(사용자 결정 A).

- **정의**: 미국 테마의 주간 뉴스 건수 = 그 테마 승인 소속(direct+partial) 기업들의 Finnhub 기업 뉴스 기사 수,
  같은 기사(URL)가 여러 소속에 걸리면 한 번만. 키워드는 쓰지 않는다.
- **한국과 정의가 다르다.** 한국은 키워드 기사 수(네이버)다. 비율(이번 주 ÷ 직전 8주 중앙값)은 각 시장 안에서만
  의미가 있고 두 시장 값을 서로 비교하지 않는다.
- **소속이 바뀌면 건수 규모가 바뀐다.** 분기 재매핑으로 소속이 크게 늘면 그 주에 가짜 급증이 날 수 있다 -
  재매핑 직후 한 주는 화살표를 그대로 믿지 말 것(현재 자동 보정 없음, 알려진 한계).
- **수집**: 주 단위 조회(한 응답이 약 250건에서 잘린다 - 8주 한 번 조회 시 BA·GE·LMT가 240-246건에서 멈춤).
  같은 종목은 주마다 한 번만 조회, 무료 등급 분당 60회. 상한 근처 응답은 saturated_members로 로그.
- **실패 처리**: 소속 중 **하나라도** 조회에 실패하면 그 테마 그 주 건수는 NULL(일부만 센 건수는 가짜 감소가 된다,
  2026-10-04 리뷰에서 '전부 실패일 때만'에서 강화). 전 테마 0건이면 기존 규칙대로 수집 실패.
- **기준선**: `NEWS_SOURCE_SWITCH_WEEK["US"] = 2026-09-28` 이후 주만 쓴다 - 4주 쌓일 때까지 미국 뉴스 축은 na.
  Finnhub에는 과거 기사가 있어 백필로 바로 기준선을 만들 수 있지만, 그러면 구글 시절 주간 기록을 덮어써야 해서
  (이력 테이블 덮어쓰기 금지) 하지 않았다.


**시장 대비 판정 (2026-11-04)**: 소속 기업 뉴스 건수는 실적 발표 철에 테마와 무관하게 다 같이 늘어난다(10/26 주 32개 중 22개 증가,
비율 중앙값 1.65). 그래서 미국 화살표는 그 주 테마 비율을 중앙값으로 나눈 값(`news_rel_ratio`)으로 판정한다. 원래 비율 `news_ratio`와
중앙값 `news_market_ratio`는 그대로 남긴다. 비율 있는 테마가 10개 미만이면 바꾸지 않는다. 대가: 시장 전체에 진짜 뉴스가 늘어난 주도
"보합"이 된다 - 이 축이 묻는 건 "다른 테마보다 더 주목받나"다. 대형주 쏠림(NVDA 등)은 이걸로 풀리지 않는다.

## 3. A-4: 실적 축

### 3.1 "매출 성장률 개선"의 정의

> **개정 이력** — 이 항목은 두 번 바뀌었다. 아래가 현재 구현이고, 원안과
> 1차 개정안은 그 뒤에 이유와 함께 남겨둔다(왜 이렇게 됐는지가 중요해서).

**현재 (2026-09-08~)**: 같은 시장 기업들의 성장률 **중앙값을 넘는가**를 본다.

```
g_yoy(기업) = (매출_t / 매출_{t-4}) - 1     ← 전년동기 대비 성장률
기준선      = 같은 시장 전 기업 g_yoy의 중앙값
개선        = g_yoy > 기준선
```

**전년동기 대비를 쓰는 이유**: 계절성 때문이다. 4분기와 1분기를 직접 비교하면 대부분의 소매·건설 기업이 "악화"로 나온다.

**필요 데이터: 최소 5개 분기.** 없으면 `insufficient_data`.
**기준선 표본이 20개 미만이면** 중앙값을 신뢰할 수 없어 절대 기준(0)으로 폴백한다.

중앙값은 **반드시 시장별로 따로** 낸다. 실측 중앙값이 미국 10.8% / 한국 18.4%로
크게 달라서, 한 덩어리로 내면 한쪽 시장이 통째로 위나 아래로 쏠린다(주가 축이
시장별 지수를 쓰는 것과 같은 이유).

**이 변경으로 의미가 달라진 점**: "실적이 좋아졌다"가 아니라 **"같은 시장
기업들보다 잘했다"**는 뜻이다. 시장 전체가 부진한 국면에서도 상위 테마는
상승으로 나올 수 있다.

up2를 주는 **상수**가 됐고(미국 14/14, 한국 7/8), 라벨이 사실상 뉴스·주가로만
결정되고 있었다. 집계 임계값(0.70)을 올려도 비율이 정확히 1.00인 테마가
미국에만 10개라 해결되지 않았다 — 문제는 임계값이 아니라 기업별 기준선이었다.

### 3.2 계산

```
대상 = theme_members WHERE theme_id=? AND approved=1
       AND linkage IN ('direct','partial')     ← 기본값

각 기업에 대해:
  5개 분기 매출 확보 실패 → insufficient (분모에서 제외)
  g_yoy > 시장 중앙값       → improved
  그 외                     → not improved

earn_ratio = improved / (members - insufficient)
```

**`linkage='peripheral'` 제외가 기본값이다.** 대형주는 사업이 많아 여러 테마에 걸리는데, 그 기업 전체 매출로 테마를 판정하면 왜곡된다. 다만 옵션으로 포함 가능하게 하고, 포함/제외 결과가 크게 다르면 화면에 표시한다.

### 3.3 판정

```
(members - insufficient) < 5     → 'na'  (표본 부족)
insufficient / members > 0.4     → 'na'  (데이터 신뢰 불가)
earn_ratio >= 0.70               → 'up2'
earn_ratio >= 0.55               → 'up1'
earn_ratio <= 0.45               → 'down'
그 외                             → 'flat'
```

**`insufficient` 비율이 40%를 넘으면 판정하지 않는다.** 남은 기업만으로 낸 비율은 그 테마를 대표하지 못한다. 이 경우 화면에 "데이터 부족"으로 표시하고 이유를 밝힌다.

### 3.4 이 축의 성질 — 화면에 반드시 표시

**실적 축은 주간 신호가 아니다.** 재무제표는 분기에만 바뀌므로, 실적 시즌을 제외하면 몇 주 동안 같은 값이 유지된다.

`earn_as_of`(기준 분기)를 화면에 항상 표시한다. 사용자가 "이 ↑↑는 이번 주 일이 아니라 지난 분기 상태"임을 알아야 한다.

## 4. A-5: 주가 축

### 4.1 계산

```
각 소속 기업의 4주 수익률 = (수정종가_금요일 / 수정종가_4주전_금요일) - 1
price_median_ret = 위 값들의 중앙값        ← 평균 아님

price_index_ret  = 시장 지수 4주 수익률
                   US → S&P 500 (^GSPC)
                   KR → KOSPI (^KS11)      ← Phase B

price_excess = price_median_ret - price_index_ret
```

**중앙값을 쓰는 이유**: 한 종목이 50% 급등하면 평균이 통째로 흔들린다. 중앙값은 "테마 전체가 움직였나"를 본다.

**반드시 수정종가(adjusted close)를 쓴다.** 액면분할·배당을 반영하지 않으면 가짜 급락이 잡힌다.

### 4.2 판정

```
가격 데이터 확보 기업 < 5   → 'na'
price_excess >= 0.08        → 'up2'
price_excess >= 0.03        → 'up1'
price_excess <= -0.03       → 'down'
그 외                        → 'flat'
```

### 4.3 주의

- 상장 4주 미만 기업은 제외 (분모에서 빼고 로그)
- 거래정지 종목은 직전 가격이 그대로 유지되어 수익률 0으로 잡힘 → 거래량 0인 날이 연속되면 제외
- 이 축은 **주가 수집 배치 호출**로 처리한다. 종목별 개별 호출 금지 (Phase 0 §7과 동일)

## 5. 조합 라벨

```
(news, earn, price) → label
```

| 뉴스 | 실적 | 주가 | 라벨 |
|---|---|---|---|
| up2 | flat | up1/up2 | Early Buzz |
| up1/up2 | up1/up2 | up1/up2 | Full Alignment |
| flat/down | up2 | flat | **Quiet Strength** |
| up2 | down | up2 | Overheated Buzz |
| down | down | down | Full Decline |
| down | up1/up2 | down | Quiet Recovery |

**위 6개에 해당하지 않으면 `label = NULL`이고 화살표만 표시한다.**

모든 조합에 이름을 붙이려 하지 말 것. 억지 분류는 정보를 더하는 게 아니라 없앤다.

**축이 하나라도 `na`이면 라벨을 붙이지 않는다.** 판정 근거가 불완전한 상태에서 이름을 붙이면 오해를 부른다.

## 6. A-6: 테마 보드 화면

### 6.1 무엇을 보여주나

**표시 대상**: 세 축 중 하나 이상이 `flat`/`na`가 아닌 테마만.

34개를 매주 다 보여줄 필요가 없다. 움직인 5~8개만 뜨는 것이 정상이다.

### 6.2 정렬 — 점수가 없으므로 그룹으로

**라벨별로 묶어서 보여준다.** 순위를 매기지 않는다.

```
1. Quiet Strength      ← 이 툴의 존재 이유. 맨 위
2. Quiet Recovery
3. Early Buzz
4. Full Alignment
5. Overheated Buzz
6. Full Decline
7. (라벨 없음 — 화살표만 움직인 것들)
```

이 순서는 **점수가 아니라 편집 방침**이다. "Quiet Strength"을 위에 두는 것은 그것이 뉴스만 봐서는 찾을 수 없는 정보이기 때문이다.

### 6.3 각 행에 들어갈 것

```
조선                →     ↑↑     →     Quiet Strength
  실적: 10개사 중 8개 매출 개선 (2026 Q2 기준)
  뉴스: 이번 주 14건 / 4주 평균 13건
  [소속 기업 보기]  [기사 보기]
```

- 숫자를 함께 보여준다. 화살표만 있으면 근거를 알 수 없다
- `earn_as_of` 항상 표시
- `insufficient` 기업이 있으면 그 수도 표시
- 기사 목록으로 이동 가능 (`theme_news`)

### 6.4 소속 기업 보기

테마를 펼치면 소속 기업 목록. **등급 없음.**

```
HD현대일렉트릭   [전력망] [데이터센터 전력]   매출↑ 마진↑   재무 통과
XX전기          [전력망]                    매출↓ 마진→   재무 통과
YY산업          [전력망]                    데이터부족     —
```

- 다른 테마에도 걸린 기업은 그 테마들을 함께 표시. **동시 소속이 정보다**
- `재무 통과`는 기존 트랩 필터 결과 그대로
- `linkage='peripheral'` 기업은 흐리게 표시하거나 별도 구분

### 6.5 하지 말 것

- 종합 점수·등급 표시
- "매수 추천", "BUY", "우선순위 A" 류의 표현
- 테마를 수익률 기대치로 정렬

## 8. 완료 조건

| 항목 | 기준 |
|---|---|
| `theme_signals`에 미국 테마 전체 행 생성 | 매주 |
| 뉴스 백필 8주 완료 | 첫 실행 전 |
| 라벨이 붙는 테마 | 주당 3~10개 (0개면 임계값이 높음, 20개 이상이면 낮음) |
| 뉴스 중복 제거율 | 로그에 기록, 주간 편차 확인 |
| `na` 비율 | 축별 30% 미만 |
| 화면 | 6.2 순서대로 그룹 표시 |

### 첫 4주에 확인할 것

임계값이 임의값이므로(마스터 계획서 §9) 다음을 본다:

- 매주 전 테마가 ↑↑ → 뉴스 임계값이 낮음
- 매주 아무것도 안 움직임 → 임계값이 높음
- 특정 테마만 계속 ↑↑ → 키워드가 너무 넓음 (일반 명사가 섞였을 가능성)
- 실적 축이 전부 `na` → `insufficient` 비율 확인. 재무 캐시 백필이 덜 됐을 가능성

**조정할 때는 통과 개수가 아니라 이유를 근거로 한다.** "너무 많이 뜬다"가 아니라 "이 테마가 뜬 게 납득이 안 된다"가 조정 근거다.

## 9. 알려진 한계

**뉴스 축은 이미 늦은 신호다.** 기사가 쏟아질 때쯤이면 대개 주가에 반영된 뒤다. 그래서 건수가 아니라 변화율을 보고, **뉴스 축 단독으로는 아무 결론도 내지 않는다.**

**실적 축은 분기에 한 번만 움직인다.** 실적 시즌 외에는 사실상 정적이다. 이건 결함이 아니라 성질이며, 그래서 `earn_as_of` 표시가 필수다.

**세 축은 독립적이지 않다.** 뉴스가 많은 테마는 주가도 오르는 경향이 있다. 즉 "3축 동시 상승"은 세 방향의 독립 검증이 아니라 하나의 현상을 세 번 본 것일 수 있다. **그래서 종합 점수를 만들지 않는다** — 합치는 순간 이 상관관계가 감춰진다.

**테마 구성원이 바뀌면 지표가 점프한다.** 분기 매핑 갱신 후 첫 주는 전주와 비교하지 말 것. `mapping_run_id`가 바뀐 주를 화면에 표시한다.
