# 1. 이 툴이 무엇이 되는가

## 한 문장

> 매주 월요일, 뉴스·실적·주가 세 축에서 움직임이 감지된 테마와
> 그 테마에서 재무가 받쳐주는 기업을 보여준다.

## 무엇이 아닌가

- 매수·매도 신호를 주는 도구가 **아니다**
- 종목을 순위 매겨 추천하는 도구가 **아니다**
- 사용자가 뉴스를 읽고 키워드를 입력해야 도는 수동 스크리너가 **아니다**

## 성공 조건

이 화면이 매주 자동으로 뜨면 성공이다.

```
이번 주 움직인 테마

                   뉴스   실적   주가
──────────────────────────────────────────
조선                →     ↑↑     →     Quiet Strength
  10개사 중 8개가 시장 중앙값 초과. 뉴스는 4주 평균 수준.

원전·SMR           ↑↑     →      ↑     Early Buzz
  뉴스 4주 평균 대비 +180%. 실적 변화는 아직 없음.

2차전지            ↑↑     ↓     ↑↑     Overheated Buzz
  뉴스·주가 급등, 12개사 중 3개만 중앙값 초과.
```

**두 번째 줄 같은 항목이 나오는 것이 이 툴의 존재 이유다.** 뉴스만 봐서는 찾을 수 없는 대상이다.

> 세 축이 각각 **무엇과 비교하는지**가 다르다 — 뉴스는 그 테마 자신의 직전 4주,
> 실적은 같은 시장 기업들의 중앙값, 주가는 그 시장 지수. 특히 실적 축은
> "좋아졌다"가 아니라 **"동종보다 앞섰다"**는 뜻이다(SPEC §3.1 개정 이력 참고).

# 2. 왜 바꾸는가 — 기존 구조의 문제

AlphaDesk(2026-08 기준)는 유니버스 573개를 재무 필터로 걸러 후보 161개를 뽑는 구조였다. 여기서 세 가지 문제가 드러났다.

**1) 발견이 일어나지 않는다.** 미국 후보 149개가 전부 S&P 500이다. 애널리스트가 이미 다 보고 있는 기업들이라, 필터를 아무리 정교하게 다듬어도 결과는 "이미 아는 회사들"이다.

**2) 시장을 읽는 기능이 없다.** 개별 기업의 재무 건전성만 판정한다. "지금 어느 산업이 움직이고 있나"에 대한 답이 없다.

**3) 밸류에이션 축과 성장 축이 통째로 없다.** 필터 6개 항목이 전부 재무 안정성이다. ROE 12% 컷은 사실상 퀄리티 팩터 스크리닝이라 오히려 비싼 인기주 쪽으로 기운다.

# 3. 설계 원칙

## 원칙 1. 단일 종합 점수·등급을 만들지 않는다

가중합 점수(품질 40 + 모멘텀 35 + 체제 25 같은 것)는 2026-08에 이미 한 번 제거했다. 근거 없는 가중치였기 때문이다. **다시 만들지 않는다.**

세 축을 각각 표시하고 해석은 사람이 한다. 이것이 "매수 신호로 오해되지 않게 하는" 문제의 해법이기도 하다. 문구로 푸는 문제가 아니다 — 화면에 A등급이 있으면 사람은 매수 신호로 읽는다. `뉴스 ↑↑ / 실적 → / 주가 ↑`는 읽는 사람이 해석을 해야 하는 형태다.

## 원칙 2. LLM은 숫자를 만들지 않는다

| LLM이 하는 일 | LLM이 하지 않는 일 |
|---|---|
| 테마에 어떤 기업이 속하는지 후보 생성 | 재무 수치 조회 |
| 왜 속하는지 근거 한 줄 작성 | 실적 개선 여부 판단 |
| 테마가 왜 움직이는지 설명 | 성장률·마진 계산 |

**모든 숫자는 `fundamentals_cache`(DART / yfinance)에서만 나온다.**

후보 생성은 틀려도 안전하다(코드가 거른다). 숫자는 틀리면 그대로 화면에 나간다.

## 원칙 3. 되돌릴 수 없는 것은 지금 심는다

나중에 소급 불가능한 것들:
- 그 시점의 재무 숫자 스냅샷 (`fetched_at`, `period_end`)
- 테마 구성원 이력 (`run_id`)
- 유니버스 출처 태그 (`universe_source`)

되돌릴 수 있는 것(임계값, 가중치, 표시 방식)은 데이터가 쌓인 뒤에 정한다.

## 원칙 4. 필터는 판정에만, 밸류에이션은 표시에만

재무 안정성(트랩 필터)은 통과/탈락을 가르는 데 쓴다. 밸류에이션과 성장은 **컬럼으로 보여주기만 하고 자르지 않는다.** 목적이 리스트업이므로 후보를 줄이는 것은 기능이 아니라 손실이다.

## 원칙 5. 결측을 정상 상태로 설계한다

한국 데이터, 신규 상장 기업, 좁은 테마 — 빈칸이 나오는 것이 기본이다. `통과 / 탈락 / 데이터부족` 3분류를 모든 판정에 적용한다. 계산 불가를 탈락으로 처리하면 성장 초기 기업이 조용히 사라진다.

# 4. 구조

## 4.1 데이터 흐름

```
[분기 1회 — 수동]
  테마→기업 매핑 (LLM 후보 생성 + 코드 검증 + 사람 승인)
        ↓
   theme_members

[주 1회 — 자동]
  ┌─ 뉴스 수집 ──→ 테마별 건수 집계 ──→ 뉴스 축
  ├─ 재무 캐시 ──→ 소속 기업 매출 개선 비율 ──→ 실적 축
  └─ 주가 수집 ──→ 소속 기업 상대강도 중앙값 ──→ 주가 축
        ↓
   theme_signals (주간 스냅샷, 영구 보존)
        ↓
   테마 보드 화면 (움직인 테마만 표시)
```

## 4.2 세 축 계산

| 축 | 계산 | 성질 |
|---|---|---|
| **뉴스** | 이번 주 건수 ÷ 직전 8주 중앙값 | 빠르지만 이미 늦은 신호 |
| **실적** | 소속 기업 중 매출 성장률이 직전 분기보다 개선된 비율 | **느리지만 진짜 신호** |
| **주가** | 소속 기업 4주 수익률 중앙값 − 시장 지수 4주 수익률 | 중간 |

각 축을 `↑↑ / ↑ / → / ↓` 4단계로 표시. 임계값은 `themes.yaml`의 `config` 블록에 있다.

**계산 시 주의:**
- 실적·주가 축은 **평균이 아니라 비율·중앙값**을 쓴다. 평균은 대형주 하나가 결과를 결정한다.
- 뉴스 축은 건수가 아니라 **변화율**이다. 최소 건수 하한(기본 10건) 미만이면 판정 보류.
- 시장 지수는 US=S&P 500, KR=KOSPI로 **각각** 비교한다.
- 실적 축은 분기에만 움직인다. 주간 신호가 아니라 "현재 상태"이며, 화면에 그렇게 표시한다.

## 4.3 조합 라벨

점수 없이 조합 패턴에서 라벨이 나온다.

| 뉴스 | 실적 | 주가 | 라벨 |
|---|---|---|---|
| ↑↑ | → | ↑ | Early Buzz |
| ↑ | ↑ | ↑ | Full Alignment |
| →/↓ | ↑↑ | → | **Quiet Strength** |
| ↑↑ | ↓ | ↑↑ | Overheated Buzz |
| ↓ | ↓ | ↓ | Full Decline |
| ↓ | ↑ | ↓ | Quiet Recovery |

**이 6개만 라벨을 단다.** 나머지 조합은 화살표만 표시한다. 모든 조합에 이름을 붙이면 오히려 정보가 사라진다.

## 4.4 기업 표시

기업에는 **등급을 붙이지 않는다.**

```
HD현대일렉트릭  [전력망] [데이터센터 전력]   매출↑ 마진↑   재무 통과
```

두 테마에 동시에 걸렸다는 사실 자체가 정보다. 등급으로 접으면 사라진다.

## 확보 가능

| 데이터 | 미국 | 한국 |
|---|---|---|
| 종목 목록·시가총액 | yfinance | 공공데이터포털 KRX API |

**한국 재무는 DART로 열린다.** 기존에 한국 후보가 12개뿐이었던 것은 데이터가 없어서가 아니라 yfinance로 받으려 했기 때문이다. 다만 계정과목 정규화와 연결/별도 구분이 필요해 며칠짜리 작업이다.

## 조달 불가 — MVP에서 제외

| 데이터 | 이유 |
|---|---|
| EPS 컨센서스·추정치 상향 | 유료 (Refinitiv / FactSet / 에프앤가이드) |
| 수주·백로그 | 정형 데이터 없음 |
| 가이던스 | 컨콜 텍스트, 정형화 안 됨 |
| 기업 이벤트 캘린더 (수주·임상·출시) | 유료 |
| 피어 그룹 자동 구성 | 난이도 높음 |

**이것들이 기획서 5-2의 "지속성" 축 전체를 차지한다.** 해당 축은 MVP에서 삭제하고 Phase 2로 옮긴다. 기획서에서 지우지 말고 "조달 불가로 보류"로 표시해 기록을 남긴다.

## 부분 대체

| 원래 원한 것 | 대체 |
|---|---|
| 수주·백로그 | DART 단일판매·공급계약 공시 (한국만, Phase 2) |
| 원가 하락 | 매출총이익률 방향 |
| 재고 정상화 | 재고 증가율 vs 매출 증가율 |
| 산업 바닥 통과 | 테마 실적 축이 이미 커버 |

## "조용히 좋아지는" 판정 (4개 항목으로 축소)

```
✅ 매출 성장률 개선 (직전 분기 대비 가속)
✅ 영업이익률 반등
✅ 영업현금흐름 개선
✅ 재고 정상화
```

원래 8개였으나 4개가 조달 불가였다. **남은 4개로 충분하다.** "뉴스 조용한데 매출 가속 + 마진 반등 + 현금흐름 개선"이면 이미 강한 신호다.

# 6. 로드맵

## Phase 0 — 안정화 (진행 전 필수)

2026-08-25 `Weekly Market Analysis`가 `YFRateLimitError`로 실패했다. 실패 지점은 야후 세션 인증(crumb) 발급 단계였고, 그 주 장기 포트폴리오 매수가 통째로 빠졌다.

**진단**: GitHub Actions 공유 IP가 금융 데이터 스크래핑용으로 이미 차단 대상이다. 한국 pykrx가 4주 연속 실패한 것과 동일한 원인이다.

| 작업 | 명세 |
|---|---|
| 재무제표 Turso 캐시 | `SPEC_fundamentals_cache.md` §2~§5 |
| rate limit 재시도 + 체크포인트 | 동 문서 §6 |
| 시가총액 배치 호출 | 동 문서 §7 |

*(동 문서 §8 "매수 단계 분리"는 포트폴리오 제거로 폐기)*

**핵심 관찰**: 트랩 필터 6개 항목은 전부 재무제표 기반이고 주가가 들어가는 항목이 하나도 없다. 재무제표는 분기마다 바뀌는데 매주 573종목을 다시 받고 있었다. 캐시하면 호출량이 10분의 1로 떨어진다.

## Phase A — 미국 시장만으로 전 파이프라인 완성

| 단계 | 내용 | 난이도 |
|---|---|---|
| A-1 | `themes.yaml` 배치 (완료) | — |
| A-2 | 테마→기업 매핑 (`SPEC_theme_company_mapping.md`) | 중 |
| A-3 | 뉴스 축 계산 | 중 |
| A-4 | 실적 축 계산 | 하 |
| A-5 | 주가 축 계산 | 하 |
| A-6 | 테마 보드 화면 | 중 |

**미국만으로 먼저 끝내는 이유**: DART 연동이 가장 크고 위험한 작업이다. 화면까지 나오고 "이게 쓸모 있나"를 판단한 뒤에 며칠을 쓰는 것이 안전하다. 미국만으로 돌려보고 별로면 DART를 안 만들어도 된다.

**Phase A에서 빈칸으로 남는 테마** (한국 전용): 조선, K-뷰티, K-푸드, K-콘텐츠. 화면이 비는 것이 정상이다.

## Phase B — 한국 추가

- DART Open API 연동 (계정과목 정규화, 연결/별도 구분)
- 한국 유니버스 정상화 (공공데이터포털 KRX API 검증)
- 전 파이프라인 재실행

## Phase C — 확장

- S&P 400 중형주 편입 (**`universe_source` 컬럼 반드시 동시 추가**)
- 밸류에이션 컬럼 (FCF Yield, PER — 표시 전용)
- 성장 컬럼 (매출 3년 CAGR + 최근 1년 + 영업이익 방향)
- 섹터 중앙값 계산기 (밸류에이션·성장 공용)

**섹터 중앙값 계산 시 주의:**
- 필터 통과 집단이 아니라 **유니버스 전체**에서 계산한다. 통과 집단은 이미 퀄리티로 걸러져 있어 중앙값이 비싼 쪽으로 올라가 있다.
- **시장별로 따로 계산한다.** 미국 기준을 한국에 적용하면 코리아 디스카운트 때문에 한국 종목이 전부 "초저평가"로 나온다.
- 평균이 아니라 중앙값. PER 음수는 제외.

## Phase 2 이후 (기획서에서 이관)

레짐 모듈 / 기업 기초조사 카드 / 가치사슬 시각화 / 피어 비교 / 일정 기능 / 한국 공급계약 공시 파싱 / 반대 논리 자동 생성

| `/workflow` 매수체크 | 매수 판단 기능 |

| `/portfolio` 실거래 기록 | 별도 대시보드로 분리하기로 결정 |
| `weekly-analysis.yml`의 매수 실행 스텝 | |

**제거 전에 확인할 것:**

1. **거시지표 수집 코드는 지우지 말 것.** 게이트 판정 로직은 제거하되, 금리·환율·유가 등을 모으는 수집기는 Phase 2 레짐 모듈에서 재사용한다. 무엇이 재사용 가능한지 목록을 먼저 뽑고 지운다.
2. **`performance-tracking.yml`은 유지한다.** 이것은 포트폴리오가 아니라 `watchlist_candidate_history`(과거 후보들의 30~730일 실제 수익률)를 계산하는 것으로, 필터가 맞는지 검증하는 유일한 장치다. 포트폴리오를 지워도 이 검증 루프는 살아남는다.

실거래 기록은 건수가 적어 백업 없이 제거한다. DB 테이블은 DROP하지 않고 코드 참조만 끊으므로 데이터 자체는 당분간 남는다.

**제거 후 남는 화면**: `/`, `/watchlist`, `/sector`, `/briefing`, `/guide` — 여기에 테마 보드가 새로 붙는다.

# 9. 이 문서에서 임의로 정한 숫자

근거 데이터 없이 시작점으로 정한 값들이다. **운영하며 조정할 것이고, 조정할 때는 통과율이 아니라 결과를 근거로 삼는다.**

- 뉴스 축: +100% → ↑↑, +30% → ↑
- 실적 축: 개선 비율 70% → ↑↑, 55% → ↑
- 주가 축: +8%p → ↑↑, +3%p → ↑
- 최소 기사 수: 10건 (좁은 테마는 6건)
- 테마별 적정 기업 수: 10~30개
- 재무 캐시 주간 갱신 예산: 60종목
- 환각 폐기율 경고선: 30%
- 워치리스트 성장 등급 경계(docs/SPEC_watchlist_growth.md, 2026-09-30): 매출 3년
  CAGR 0% 미만 → 역성장, 0~10% → 정체, 10% 이상 → 성장. 0%는 임의값이 아니다
  ("매출이 줄었다"는 사실의 경계). 10%는 워치리스트 후보(KR 121·US 154) 실측
  분포에서 고른 시작점 - 이 선에서 KR 47%·US 35%가 "성장"이 된다.

**2026-08-21에 트랩 필터 기준을 상향한 근거는 "통과율 53%가 너무 느슨해 보여서"였다.** 이것은 결과가 아니라 개수로 임계값을 맞춘 것이다. 같은 실수를 반복하지 않는다. `performance-tracking` 데이터가 쌓이면 임계값이 실제 결과 차이를 만드는지 역으로 확인한다.

단, 그 검증의 한계도 인정한다. 주 1회 × 161종목은 같은 종목이 반복되는 것이라 실질 표본은 종목 수 수준이고, 1년은 시장 국면 하나다. **검증 목표는 "임계값 확정"이 아니라 "방향 감각과 극단값 확인"이다.**
