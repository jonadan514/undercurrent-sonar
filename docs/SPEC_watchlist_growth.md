# 워치리스트에 성장 축 추가

작성 2026-09-29. 조사 결과는 Actions 실행 두 건으로 실측한 것이다
(`probe-growth-fcf-data.yml`, run 36517963608 / 36518154541).

## 1. 왜 지금 이것인가

워치리스트가 보여주는 축은 지금 둘이다.

- **튼튼한가** - F-Score, 부채비율, 이자보상, 체제 (함정 필터)
- **싼가** - PSR/PER, 밸류 등급 (2026-09-24 추가)

**자라는가**가 비어 있다. 그리고 이건 단순히 "축이 하나 없다"가 아니라,
**지난주에 넣은 "싼 편만" 필터의 빈 구멍**이다.

함정 필터는 *재무 부실*을 걸러낸다(F-Score, 부채, 이자보상). 그런데 **완만한
구조적 쇠퇴**는 걸러내지 못한다. 무차입에 흑자인데 매출이 3년째 줄고 있는
기업은 함정 필터를 전부 통과하고, 시장이 그걸 알아서 주가를 깎아놨기 때문에
PSR이 낮아 **"싼 편"으로 올라온다.** 고전적인 가치 함정이고, 지금 화면에서는
구분할 방법이 없다.

실측으로도 그 집단이 존재한다: 3년 CAGR이 음수인 후보가 한국 17종목,
미국 11종목이다.

## 2. 조사 결과 (실측)

### 데이터는 충분하다

워치리스트 후보(KR 121 / US 154) 기준, `fundamentals_cache`의 연차 재무제표:

| | 연차 손익 4개년+ | 연차 현금흐름 4개년+ | 계산 성공률 |
|---|---|---|---|
| KR | 120/121 (99%) | 99% | 120/121 (99%) |
| US | 154/154 (100%) | 100% | 153/154 (99%) |

- 매출 계정은 양 시장 모두 `Total Revenue`(US는 `Operating Revenue`도 함께).
- 영업이익 계정도 들어온다(계정없음 KR 2 / US 3종목).
- 현금흐름표에 **`Free Cash Flow`가 직접 있다** - 영업현금흐름 - 자본지출로
  만들 필요가 없다(3장 참고).
- `quarterly_financials_raw`는 2년치(2025-2026)뿐이라 **3년 지표의 소스가 될 수
  없다.** 연차 재무제표를 쓴다.

### 엄격한 규칙이 공짜였다

"최근 4개 회계기간의 연도 간격이 정확히 3년이어야 한다"는 규칙
(`company_valuation._last_4q_sum`의 "연속 4분기"와 같은 엄격함)으로 탈락한
종목은 **0개**였다. 실패는 회계기간이 3개뿐인 1종목, 매출 계정이 없는
1종목이 전부다. 규칙을 느슨하게 할 이유가 없다.

### 분포 - 이게 설계를 하나 결정했다

매출 3년 CAGR:

| | 최소 | 25% | 중앙 | 75% | 최대 |
|---|---|---|---|---|---|
| KR (n=120) | -13.2% | +3.3% | **+9.2%** | +21.0% | +725% |
| US (n=153) | -14.1% | +3.3% | **+7.4%** | +11.7% | +49.3% |

누적 비율:

| 기준 | KR | US |
|---|---|---|
| 0% 이상 | 86% | 93% |
| +10% 이상 | 47% | 35% |
| +20% 이상 | 28% | 7% |

**밸류처럼 순위 3등분을 하면 안 된다.** 후보의 86-93%가 실제로 성장 중이라,
하위 1/3을 "역성장"이라고 부르면 +3%로 성장 중인 기업에 거짓 라벨이 붙는다.
밸류(PSR)는 "비싼지 싼지"에 절대 기준이 없어서 상대 순위가 맞았지만, 성장은
**0%라는 절대 기준선이 그 자체로 의미**가 있다(매출이 줄었다는 건 비교 대상
없이도 사실이다).

-> **성장 등급은 절대 기준을 쓴다.**

## 3. 이번에 하는 것 / 안 하는 것

### 한다 - 매출 성장 (3년 CAGR + 최근 1년) + 영업이익률 방향

### 하지 않는다 - FCF Yield (이번엔)

데이터는 확인됐다(양 시장 100%, `Free Cash Flow` 직접 항목). 그런데도 미루는 이유:

1. 밸류 축엔 이미 지표가 둘(PSR·PER) 있고 성장 축은 0개다. 빈 축을 먼저 채운다.
2. FCF는 해마다 출렁인다. 설비투자 한 번 크게 한 해에 음수로 뒤집힌다.
   제대로 쓰려면 다년 평균을 정해야 하고, 그건 별도 설계가 필요하다.
3. 표에 넣을 자리가 없다(아래 참고).

**나중에 넣는다면 표가 아니라 상세 카드에** 넣는다. 자본집약적인 업종
(조선·반도체 장비·건설 - 한국 후보에 많다)에서 PER이 못 보는 걸 보여주므로
가치는 분명히 있다. 데이터가 있다는 것만 확인해 두고 넘긴다.

### 컬럼 자리 문제 (알고 넘어가는 비용)

표는 이미 13칸이고 가로 스크롤이 걸려 있다. 여기에 2칸(성장 등급, `3년/1년`)을
더하면 15칸이 된다. 대안은 등급만 표에 넣고 숫자는 상세 카드로 보내는 것(1칸)인데,
**숫자도 표에 둔다.** 밸류에서 이미 같은 판단을 했고(PSR 0.25와 0.9는 둘 다
"싼 편"이지만 다른 종목이다), 성장도 +3%와 +40%가 둘 다 "성장"이라 행끼리
비교하려면 숫자가 보여야 한다. 아이디어를 훑는 게 이 화면의 용도다.

(`현재가`·`섹터` 칸을 빼서 자리를 만드는 선택지가 있지만 이번 작업 범위 밖이다 -
필요하면 따로 결정한다.)

## 4. 계산 규칙

### 4-1. 소스

`fundamentals_cache`의 `statement = 'income'` 행. `period_end`(ISO 날짜)를
**내림차순 정렬**해 최근 4개 시점을 쓴다. ISO 날짜라 문자열 정렬이 곧 날짜
정렬이다.

계정 이름은 순서대로 시도한다(실측에서 이 목록으로 99% 성공):

```python
REVENUE_KEYS = ("Total Revenue", "Operating Revenue")
OPERATING_INCOME_KEYS = ("Operating Income", "Total Operating Income As Reported", "EBIT")
```

### 4-2. 값

```
매출 3년 CAGR = (최신매출 / 3년전매출) ** (1/3) - 1
최근 1년      = 최신매출 / 직전매출 - 1
영업이익률 방향 = (최신 영업이익/매출) > (3년전 영업이익/매출) ? "개선" : "악화"
```

**None을 돌려주는 경우** (원칙 4 - 계산 불가를 탈락으로 만들지 않는다):

- 회계기간이 4개 미만
- 최근 4개 시점의 연도 간격이 정확히 3년이 아님
- 매출 계정이 없음
- 최신 또는 기준 시점 매출이 0 이하 (성장률이 정의되지 않는다)
- 영업이익률 방향은 별도로 판단 - 영업이익 계정이 없으면 방향만 None이고
  CAGR은 그대로 살린다

### 4-3. 성장 등급 (절대 기준)

```
역성장   CAGR < 0%
정체     0% <= CAGR < 10%
성장     CAGR >= 10%
```

**이 두 숫자(0%, 10%)는 실측 분포에서 고른 시작점이다** (MASTER_PLAN §9의
"임의로 정한 숫자" 항목에 추가할 것). 근거와 결과:

- `0%`는 임의값이 아니다. "매출이 3년간 줄었다"는 사실의 경계다.
- `10%`는 분포에서 골랐다. 이 선에서 KR 47% / US 35%가 "성장"이 된다.
  15%로 올리면 US가 13%까지 떨어져 한쪽 시장에서 거의 빈 칸이 된다.
- 결과 분포: KR 성장 47% / 정체 39% / 역성장 14%,
  US 성장 35% / 정체 58% / 역성장 7%.

**시장별로 나누지 않는다.** ROE(미국 12%/한국 8%)나 뉴스 비율처럼 시장별
기준을 쓰는 항목들이 있지만, 그건 측정 편향(코리아 디스카운트 등)을 보정하는
경우였다. 한국 후보의 성장률이 더 높은 건 측정 문제가 아니라 실제 차이(한국
후보에 중소형 고성장주가 더 많다)라서, 보정하면 사실을 지운다.

소수점 경계는 곱셈으로 비교한다(`0.19999999999999996` 사건 - 부동소수점
경계에서 `>=` 비교가 어긋나는 것을 이미 한 번 겪었다).

## 5. 구현 순서

### 5-1. `src/analyzers/company_growth.py` (신규)

순수 함수만. 네트워크·DB 접근 없음. `company_valuation.py`와 같은 구조로 만든다.

```python
GROWING = "성장"; FLAT = "정체"; SHRINKING = "역성장"

def revenue_cagr(periods) -> float | None
def revenue_yoy(periods) -> float | None
def operating_margin_direction(periods) -> str | None   # "개선" | "악화" | None
def growth_tier(cagr: float | None) -> str | None
```

`periods`의 입력 계약은 `[(period_end: str, data: dict), ...]` **최신순 정렬된
리스트**로 고정한다(`company_valuation`이 `select_quarters()` 리스트를 요구하는
것과 같은 방식 - 정렬을 호출부 책임으로 두지 말고 모듈 안에서 한 번 더 확인할 것).

### 5-2. `scripts/compute_watchlist_valuation.py` 확장

새 스크립트를 만들지 않는다. 같은 후보 집합을 읽고 같은 표에 쓰는 작업이라
두 번 돌 이유가 없다 - 주간 파이프라인 단계도 하나로 유지된다.

- `LATE_COLUMNS`에 `revenue_cagr_3y REAL`, `revenue_yoy REAL`,
  `op_margin_direction TEXT`, `growth_tier TEXT` 추가.
  (`ALTER TABLE ... ADD COLUMN`을 try/except로 감싸는 기존 방식 그대로)
- 연차 손익을 배치로 읽는 함수를 추가한다. 종목당 한 번씩 조회하면 운영
  DB(Turso HTTP)에 275번 왕복이 생긴다 - `IN (...)` 한 번으로 묶을 것
  (`select_quarters_bulk`와 같은 이유).
- UPDATE 문에 새 컬럼 4개를 더한다. 기존 배치 쓰기(50개씩)를 그대로 쓴다.
- 로그에 **분포를 남긴다** - PSR 최소/중앙/최대를 남기는 것과 같은 방식으로
  CAGR 분포와 등급별 종목 수를 찍는다. 11월 기준값 재검토 때 근거가 된다.

**파일 이름은 그대로 둔다.** `compute_watchlist_valuation.py`가 성장까지
계산하게 되어 이름이 정확하지 않지만, 이름을 바꾸면 워크플로 파일도 바꿔야 하고
`workflow_dispatch`가 기본 브랜치의 YAML만 찾기 때문에 main 재등록이 또
필요해진다. 그 비용에 비해 얻는 게 이름뿐이라 파일 상단 주석으로 "밸류와 성장을
같이 채운다"고 밝히는 쪽을 택한다.

### 5-3. `run_watchlist_screen.py` - 건드릴 것 없음

이미 Turso 업로드 직후 `compute_watchlist_valuation.run()`을 부르고 있다.
그 함수가 성장까지 채우게 되므로 호출부는 그대로다. (주간 스크리닝이 매주
시장 행을 지우고 새로 넣기 때문에 이 단계가 반드시 뒤따라야 한다는 조건도 동일.)

### 5-4. `frontend/app/api/watchlist/candidates/route.ts`

- `VALUE_COLS`에 새 컬럼 4개 추가.
- **폴백 경로를 그대로 유지할 것.** 컬럼이 아직 없는 DB에 이 화면이 먼저
  배포되면 SELECT가 죽고, 기존 catch가 그걸 빈 목록으로 바꿔 후보 275종목이
  0종목으로 보인다. 지난번에 그래서 `BASE_COLS` 폴백을 넣었다 - 새 컬럼도
  같은 보호를 받아야 한다.
- `growth` 쿼리 파라미터를 `valuation`과 같은 방식으로 추가.

### 5-5. `frontend/app/watchlist/page.tsx`

- `Candidate`에 `revenue_cagr_3y`, `revenue_yoy`, `op_margin_direction`,
  `growth_tier` 추가 (전부 optional·nullable).
- 표에 2칸: `성장`(배지) / `3년 / 1년`(숫자). `밸류` 칸 바로 뒤에 둔다 -
  "싼가" 옆에 "자라는가"가 붙어야 가치 함정이 눈에 보인다.
- 배지 색: 성장 = `GOOD`, 정체 = `WARN`, 역성장 = **`CAUTION`**.
  **`BAD`(빨강)를 쓰지 않는다** - 빨강은 재무 탈락(F-Score 등)에 쓰는 색이고,
  역성장은 재무 부실이 아니다. 밸류에서 "비싼 편"에 CAUTION까지만 쓴 것과 같은 규칙.
- 값이 없으면 `-` (데이터부족). 절대 0%나 "역성장"으로 표시하지 않는다.
- 필터 줄에 `성장만 (N)` 버튼 추가. 기존 필터들과 **AND로 결합**된다.
  - 이러면 사용자가 `싼 편만` + `성장만`을 직접 눌러 조합할 수 있다.
    **이걸 하나의 배지나 점수로 합치지 않는다**(원칙 1). 조합은 사용자가
    버튼을 눌러 만드는 것이지 내가 계산해서 주는 등급이 아니다.
- ⓘ 설명(`INDICATOR_INFO`)에 `growth` 항목 추가 - 기준값(0%, 10%)과 "절대
  기준이며 순위가 아니다"를 밝힐 것.
- 상세 카드에 `영업이익률 방향`을 한 줄 추가(표에는 넣지 않는다 - 성장의
  질을 보는 보조 지표라 훑어보는 대상이 아니다).

### 5-6. 테스트 `tests/test_company_growth.py` (신규)

네트워크·운영 DB·LLM 금지. 순수 함수만 검증한다.

- CAGR 계산이 맞는가 (100 -> 133.1이면 정확히 10%)
- 회계기간 4개 미만 -> None
- 연도 간격이 3년이 아니면 -> None (2026/2025/2024/2022 같은 입력)
- 매출 0 또는 음수 -> None
- 등급 경계: CAGR 정확히 0%는 `정체`, 정확히 10%는 `성장`
  (소수점 경계를 곱셈 비교로 - `0.1`이 이진수로 정확히 표현되지 않는다)
- **데이터부족이 역성장으로 새지 않는가** - `growth_tier(None)`은 `None`이지
  `역성장`이 아니다 (원칙 4)
- 영업이익 계정이 없어도 CAGR은 살아남는가

## 6. 이 작업이 하지 않는 것

- **종합 점수·순위를 만들지 않는다.** 성장은 독립된 축으로 표시되고, 밸류와의
  조합은 사용자가 필터 버튼으로 만든다.
- **성장률로 정렬하지 않는다.** 표 정렬은 지금처럼 `market, symbol` 고정.
- **함정 필터에 성장 조건을 넣지 않는다.** 원칙 3(기준값 임의 변경 금지).
  역성장은 후보에서 빼는 사유가 아니라 화면에 보여줄 사실이다.
- **FCF Yield는 이번에 넣지 않는다** (3장).
- **섹터 중앙값 계산기(Phase C)는 별도 작업.** 지금 밸류 등급이 "통과 집단 안에서"
  계산되는 것을 "유니버스 전체 기준"으로 바꾸자는 제안인데, 표시 문구가 이미
  "같은 시장 후보 중"이라고 정확히 밝히고 있어 거짓은 아니다. 가치는 있지만
  별개 판단이라 섞지 않는다.

## 부록. FCF 수익률 추가 (2026-10-19)

3장에서 미룬 FCF Yield를 3장의 조건대로 넣었다 - **표가 아니라 상세 카드에, 등급 없이.**

- 대표값: 최근 3개 회계연도 FCF 평균 / 현재 시가총액(`fcf_yield_3y`). 3개 연도가 연속(간격 정확히 2년)이
  아니면 None. 3장 이유 2(해마다 출렁임)에 대한 답이 3년 평균이다.
- 함께 보여주는 것: 최근 1개 연도 값(`fcf_yield_latest`, `fcf_latest_year`), 3년 중 음수인 해 수
  (`fcf_negative_years`) - 평균이 양수여도 설비투자 한 해가 섞였는지 보이게.
- FCF 계정: `Free Cash Flow` 직접 항목, 없으면 영업현금흐름 - |자본지출|. 둘 중 하나라도 없으면 그 해는 없음.
- 등급·필터·색 판정 없음: 업종마다 정상 범위가 너무 달라(소프트웨어 vs 조선) 기준선 하나가 거짓 라벨을
  만든다. 음수만 주의 색.
- 코드: `src/analyzers/company_cashflow.py`(순수 함수), `scripts/compute_watchlist_valuation.py`(LATE_COLUMNS 4개),
  API는 가장 바깥 계층 `FCF_COLS`. 테스트: `test_company_cashflow.py` 9개 + 배관 2개.
- 금융업 제외(같은 날 실측 후 추가): 첫 계산에서 상위가 현대해상 62%, Synchrony 37%, RenaissanceRe 21%였다.
  은행·보험사는 예금·보험료 흐름이 영업현금흐름에 섞여 FCF가 사업의 현금 창출을 뜻하지 않는다.
  trap_filter.FINANCIAL_SECTORS(부채비율 제외와 같은 목록)에 걸리면 계산하지 않고 화면에 "해당 없음 (금융업)".
